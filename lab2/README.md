# Лабораторная работа №2 — Межпроцессное взаимодействие (вариант 4)

Реализован сценарий «Волк и козлята» в независимой конфигурации «один к одному».
Хост и клиент взаимодействуют через три типа каналов: `mmap`, `shm_open+mmap` и `FIFO`
(типовые коды `mmap`, `shm`, `fifo`). Для каждого типа автоматически собираются
исполняемые файлы `host_*` и `client_*`.

## Структура

- `build.sh` — обёртка над `cmake`, очищает и пересобирает проект.
- `CMakeLists.txt` — собирает по два бинарника для каждого `conn_*.cpp`.
- `src/conn_*.cpp` — реализации транспорта (общая анонимная память, `shm_open`, FIFO).
- `src/host.cpp`, `src/client.cpp` — точки входа. Код `main` одинаковый для всех
  типов и определяется макросом `TYPE_CODE`, который задаётся при сборке.

## Сборка

```bash
cd lab2
./build.sh
```

Готовые бинарники лежат в `lab2/build`.

## Запуск

1. На стороне хоста:
   ```bash
   ./build/host_mmap --channel demo
   ```
   В выводе появится PID и готовая команда для клиента.

2. На стороне клиента:
   ```bash
   ./build/client_mmap --channel demo --host-pid <pid из лога хоста>
   ```

Доступны также `host_shm` / `client_shm` и `host_fifo` / `client_fifo`.

## Особенности реализации

- Знакомство выполняется сигналом `SIGUSR1`. Клиент отправляет сигнал по указанному PID,
  хост начинает игру только после получения сигнала.
- Синхронизация чтения/записи реализована именованными семафорами `sem_open`, все ожидания
  имеют таймаут 5 секунд. При превышении таймаута соединение разрывается.
- Игровой цикл хоста выводит подробные логи: числа волка и козлёнка, статусы «жив/мёртв»,
  счётчики спрятавшихся и пойманных. Клиент логирует статусы, полученные от хоста.
- Хост завершает игру, если два раунда подряд козлёнок мёртв. Перед завершением
  отправляется сообщение `Terminate`.

## Тестирование

Проверка проводилась на связке `host_mmap`/`client_mmap` с каналом `demo`. Клиент успешно
отправляет `SIGUSR1`, участвует в раундах и получает статусы, хост по таймаутам выбирает
случайные числа, фиксирует спрятавшихся/пойманных и корректно завершает игру после двух
подряд «мёртвых» раундов. Пример вывода:

```
Хост:
[INFO] Хост готов. PID 63411. Ожидаю сигнал от клиента.
[INFO] Сигнал получен, начинаем игру.
[INFO] Раунд 4: волк выбросил 26
[INFO] Козлёнок выбросил 100. Козлёнок пойман.
[INFO] Раунд 5: волк выбросил 4
[INFO] Козлёнок остаётся мёртвым.
[INFO] Игра завершена: два раунда подряд козлёнок мёртв.

Клиент:
[INFO] SIGUSR1 отправлен процессу 63411
[INFO] Раунд 1: моё число 90, статус: жив
[INFO] Раунд 4: моё число 100, статус: мёртв
[INFO] Раунд 5: моё число 44, статус: мёртв
[INFO] Получен сигнал завершения от хоста.
```

По аналогии можно запускать `host_shm`/`client_shm` и `host_fifo`/`client_fifo`.
